# StudyTrail 项目文档（完善版）

本文档在原《产品研究与我产品的创意》基础上，补充原型实现、技术方案与部署说明。

## 1. 产品定位（回顾）

- **解决的问题**：学习材料散落在课件、录播、微信群笔记、链接等多个地方，形不成知识全貌，也没有机制保证复习。
- **目标用户**：大学生与自学者，尤其是需要在有限时间内把大量杂乱材料转化为结构化理解的人。
- **产品形态**：移动优先的网页应用；不是又一个笔记应用，而是一张自动维护的「我学过什么、接下来该复习什么」的地图。

## 2. 核心用户旅程

1. **收集**：用户粘贴任意学习材料（标题可选、主题可选）。
2. **生成**：系统自动切分句子、识别定义句与高频考点，生成知识卡片并挂到主题地图。
3. **复习**：每天打开「今日复习」，系统按间隔重复算法呈现到期卡片，挖空式提问，用户自评回忆质量。
4. **洞察**：「数据统计」页展示各主题掌握度，用户一眼看到薄弱环节。

## 3. 原型 v0.1 范围与取舍

| 做了 | 没做（原因） |
|------|--------------|
| 知识地图（主题 → 卡片 → 掌握状态） | 账号系统（原型用 localStorage 即可验证价值） |
| 规则式本地卡片生成（定义句 + N-gram 关键词） | 真实 LLM API（需要密钥与成本，接口已隔离，可无缝替换） |
| SM-2 简化版间隔重复 + 挖空测验 | 文件上传 / OCR（v0.2） |
| 掌握度统计仪表盘 | 主题关系图谱可视化（v0.3） |

**关键取舍**：原型阶段的目标是验证「材料 → 卡片 → 复习」这条核心循环是否成立，因此把所有工程预算集中在闭环本身，其余全部砍掉或后置。

## 4. 技术方案

- 纯静态前端：`index.html` + `style.css` + `app.js`（原生 JS，零依赖）。
- 数据层：`localStorage`，键 `studytrail.v1`，结构 `{ topics, cards, reviews }`。
- 卡片生成：`generateCards()` 负责句子切分 → 定义句式匹配 / 关键词频次抽取 → 卡片构建；该函数是接 LLM 的唯一替换点。
- 间隔重复：每张卡片维护 `ease / interval / reps / streak / due`，评分 0/2/4/5 映射为忘却（10 分钟重练）与不同强度的间隔倍增；连续答对 2 次标记已掌握。
- 安全：所有用户内容经 `esc()` HTML 转义后再渲染，防止 XSS。
